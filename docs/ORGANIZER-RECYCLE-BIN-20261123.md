# Golden Himal Voice｜主辦後台資源回收桶（2026年11月23日）

本單只屬於 TEST 平台，現有正式選手資料不應因本草稿 PR 直接修改。

## 主辦方操作
1. 主辦使用受邀帳號登入後台，打開「選手名單管理」。
2. 預設顯示「現有選手」（有效＋已停用）；可用姓名、歌名、報名編號搜尋。
3. 每位選手左方有核取方塊。「全選本頁」最多只選當前顯示的25筆，不會跨頁、跨篩選條件清理。
4. 勾選後按「移到資源回收桶」，系統先向後端取得不可隨意改寫的預覽，核對可處理人數及受保護數量。
5. 必須再次輸入確認文字「移到回收桶」才送出；每10筆分段處理，每段由 D1 回傳實際結果，途中網路錯誤不猜測成功。
6. 回到選手名單，將「資料狀態」改成「資源回收桶」，勾選要恢復的選手，再按「還原所選」；輸入「確認還原」，系統再由資料庫確認。
7. 主辦仍可點選單筆選手修改、停用、移到回收桶或復原，保留操作紀錄。

## 安全設計與使用界線
- 技術上使用 e2e_registration_controls.state='deleted' 表示軟刪除，沒有 SQL DELETE e2e_applications、demo、評分、晉級及 staff audit。
- 後端只允許主辦角色提交批次；選取每筆 UUID 必須合法、沒有重複、存在、狀態吻合，且最多25筆。預覽凍結當下 version/updated_at；後續資料若變動或新增評分/晉級保護即拒絕或跳過。
- 存在的批次不可任意重複生效；結果以 D1 稽核事件與回讀確認。已評分/晉級紀錄受保護，不能用一般批次清理；完整歷史不物理移除。
- 主辦、評審、一般參賽者仍透過各自權限隔離；回收資料不出現在正常名單與評審工作清單。
- 回收桶的永久刪除本次**不啟用**。未定義主辦雙人授權、保存期限、隱私刪除法定需求、獨立備份與還原演練之前，不提供一鍵不可逆清空選手功能。資料主體要求刪除，應走既有合規資料刪除流程。
- 預設不顯示舊有「批次清理全部測試報名」危險入口，保留老的測試 API 相容性；正式作業只透過勾選名單的可審核入口。

## 放行
- 全套 Node 測試、隱私掃描、瀏覽器/workerd 三語／手機回歸必須通過。
- 必須確認只整理明確勾選的選手、部分選取、回收、還原後資料與作品數量一致；專屬評審名冊不含已回收資料。
- 在真實 Cloudflare 上需再次做受邀主辦測試、資料備份與滾回點驗證、部署 SHA 回讀；只在明確獲准之後合併部署。
- 本 PR 不碰 #199 報名流程、#200 加密備份／監控、#201 開放日期倒數功能，正式整合前要確定三個草稿分支的相依和衝突。
